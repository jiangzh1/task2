# 步骤03——表情包官方标签核验与文本情感标注小试验

## 目标

按照论文定义构建“情感冲突/情感一致”二分类标签，并将核验、修正后的离散表情包类别作为表情包情感真值。

## 已确定的执行原则

1. 原始记录直接来自 STICKERCONV 官方 Parquet 文件，不使用旧版 Cleaned/Refined 文件中的情感判断结果。
2. 最终表情包标签必须属于 SER30K 官方七类情感之一。
3. 默认保留 `origin_anno`；只有基于实际图像的核验发现明确错标时才进行修正。所有修正均单独记录，不静默覆盖原始数据。
4. 自由文本字段 `emotion` 仅作为辅助证据，不能直接作为最终表情包标签。
5. 文本情感由本地大模型独立推断。最终数据集标签始终只有“冲突”和“一致”两类。

## 小试验计划

- 采用固定随机种子，从每个官方表情包情感类别中确定性抽取最多30条目标样本。
- 使用本地视觉语言模型，根据实际表情包图像核验 `origin_anno`。
- 使用本地文本模型独立判断当前话语的情感极性。
- 在冻结全量数据处理规则前，对不同的极性映射方式和二分类冲突规则进行小规模测试。
- 保存每次模型调用的原始响应、模型标识、提示词版本和标签修正理由。

## 与 STICKERCONV Reviewer 的关系

STICKERCONV 的 Manager Agent 会在对话生成阶段检查消息与表情包之间是否存在明显不一致。该机制属于对话生成质量控制，并不是公开的数据集“冲突/一致”标注流程：它不提供逐轮文本情感类别、修正后的七分类表情包标签，也不提供本论文需要的二分类标签。因此，本实验可以借鉴其语义审核思想，但不能把它的输出直接作为本研究的标注真值。
