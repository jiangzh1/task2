## Refined 数据审计

### 训练集完整性问题

- 10,785 行中只有 10,783 个唯一会话 ID
- 缺失会话：`SESS_02514`、`SESS_02815`
- 重复会话：`SESS_02560`、`SESS_02558`
- 发生 2,181 次 ID 逆序跳转，说明输出顺序已被并发写入打乱
- 6,999 个对话轮次为 `ERROR_LLM`
- 753 个会话的顶层冲突标签为 `-2`

### 验证集与测试集

- 会话 ID 集合完整，没有重复或缺失
- 但输出顺序同样被打乱：Validation 205 次逆序，Test 288 次逆序

### 标签漂移

Refined 后的冲突样本数量相较 Cleaned 明显变化：

| Split | Cleaned 冲突 | Refined 冲突 | Refined 错误会话 |
|---|---:|---:|---:|
| Train | 1,346 | 586 | 753 |
| Validation | 108 | 54 | 0 |
| Test | 130 | 94 | 0 |

这说明冲突标签高度依赖情感分类器，必须引入可复现的分类规则、置信度和人工抽样验证。

## 现有代码风险

1. `text_emo.py` 保留 `lines = lines[0:2]` 调试截断，不能用于全量处理。
2. `text_emo_fwq.py` 使用 `as_completed` 写入，破坏输入顺序。
3. 该脚本以“输出行数”作为断点续传位置；一旦并发顺序改变或某条失败，续传会跳过错误的输入记录。
4. 失败调用被写为 `ERROR_LLM` / `-2`，但当前没有重试队列和最终错误门禁。
5. Cleaned 与 Refined 文件缺少模型版本、提示词版本、运行时间、随机种子和输入文件校验信息。

## 决策与下一步

下一步骤定义为 `step01_dataset_manifest`，目标是建立不可变、可追踪的数据清单，而不是直接覆盖现有 Refined 文件：

1. 从 Cleaned 文件读取会话，按 `session_id` 恢复稳定顺序。
2. 为每个训练目标建立唯一 `sample_id`，明确当前轮、历史上下文、目标图片和原始标签。
3. 生成独立的弱标签字段、置信度、标注模型元数据和错误状态，不把失败值混入正式标签。
4. 检查会话、图片和未来说话人层面的训练/验证/测试泄漏。
5. 输出数据统计和人工抽样清单。
6. 通过门禁后，再进入小规模情感 TTS 原型。
