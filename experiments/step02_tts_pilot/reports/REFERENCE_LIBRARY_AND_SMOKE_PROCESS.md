# EmoVoice 参考语音库与冒烟推理过程报告

## 当前结论

- RAVDESS 与 CREMA-D 已完成下载并通过文件完整性校验。
- 已从两套数据中提取中性参考语音，构建出 1183 条、115 名说话人的参考库。
- 28 条试点样本已完成参考说话人分配；训练、验证、测试的说话人集合严格互斥。
- EmoVoice 环境、模型资产、GPU 装载与波形解码链路已经打通；单条冒烟音频已成功生成并通过基础波形质检。本报告尚不是语音生成阶段最终报告。

## 下载与完整性

- RAVDESS 压缩包：208,468,073 字节，MD5 为 `bc696df654c87fed845eb13823edef8a`，与预期值一致。
- CREMA-D：四个 Parquet 分片均通过下载后记录的 SHA-256 校验。
- 网络中断没有导致重新下载；下载脚本使用断点续传/重试，恢复连接后文件已完整。

## 参考语音质检修正

初版质检直接在原始整段波形上计算 RMS 和静音占比，导致 RAVDESS 的 96 条中性语音只有 1 条通过。检查指标后确认：RAVDESS 文件时长正常，但首尾留白较长且录音电平较低。因此，初版结果反映的是质检规则与语料录制方式不匹配，而不是文件损坏。

修正后的预处理为：

1. 转为单声道并消除直流偏置；
2. 仅裁剪首尾静音，保留句中自然停顿，边缘各保留 150 ms；
3. 进行保守峰值归一化，最大增益限制为 12 倍；
4. 再执行原有时长、RMS、峰值与静音占比质检。

修正后结果：1183/1183 条通过，其中 RAVDESS 96 条、CREMA-D 1087 条，共覆盖 115 名说话人。该修正没有改变情感标签，也没有凭模型重新标注参考语音；只处理波形留白和电平。

## 参考说话人分配

- 可用说话人按稳定哈希划分为训练 93 名、验证 11 名、测试 11 名。
- 三个划分之间的说话人交集均为空，避免同一说话人跨划分造成音色泄漏。
- 28 条试点样本均已获得确定的中性参考音频路径。

## 冒烟推理排障记录

1. 首次启动失败：缺少 `pkg_resources`。已将项目虚拟环境中的 `setuptools` 固定为 80.9.0。
2. 第二次启动失败：CosyVoice 本地资产路径少了一层目录。已改为实际下载目录。
3. 第三次启动失败：HyperPyYAML 1.2.2 与 ruamel.yaml 0.19.1 不兼容。已将 ruamel.yaml 固定为 0.18.6。
4. 第四次启动越过依赖和模型装载，但输入 JSONL 使用相对路径；Hydra 切换工作目录后无法找到文件。已在启动脚本中将输入转换为绝对路径。
5. 当前重跑已使用绝对路径启动，正在等待首条 wav 及 16 kHz 转码质检结果。
6. 绝对路径修正后已进入推理循环，但官方数据加载器在推理模式下仍要求 `answer_cosyvoice_speech_token`。试点输入原先缺少该字段，因而在目标 token 整理阶段报错。现已按官方函数逻辑加入空列表占位；它只会转换为结束/填充 token，不作为待生成语音的条件，也不改变文本、情感或标签。修正后的冒烟任务已重新启动。
7. 加入占位后，模型成功完成 145 步语音 token 推理（约 11.9 秒），说明核心 EmoVoice 推理链路可运行；但波形解码阶段发现 `neutral_speaker_wav` 仍为相对路径。原因同样是推理入口切换到了源码目录。现已将所有参考 wav 路径固化为服务器绝对路径并重启冒烟任务。
8. 绝对参考路径修正后，首条音频成功生成：原始采样率 22.05 kHz，随后转换为 16 kHz；时长 8.7308 秒，RMS 0.075385，峰值 0.7381085，基础波形质检通过。语音 token 推理约 11.39 秒，连同 CosyVoice 波形解码约 21.18 秒（不含首次模型加载）。
9. 已启动 28 条平衡试点的一次性连续生成，整个批次只加载一次模型。
10. 用户试听首条 Anger 样本后反馈：吐字清晰，但主观听感平静、略带悲伤，未体现愤怒。经复核，七类 `origin_anno=Anger` 作为语音目标、三极性 `Negative` 仅用于冲突判断的设计是正确的，问题属于情感控制效果而非标签错误。为避免继续生成弱情感样本，28 条任务在产出 6 条后停止，这些输出仅作失败对照，不纳入正式数据。
11. 当前使用同一文本、同一参考说话人，对 `angry`、`strong anger, tense and forceful`、`furious, intense anger, sharp emphasis and raised energy` 三种提示做强度探针；三条在同一进程中生成。通过人工试听选择提示，若三者仍无明显愤怒，则说明不能仅靠提示词解决，需要更换/补充情感语音生成模型或调整参考语音策略。
12. 三条愤怒强度探针已全部生成并通过基础波形质检，已下载到本机试听目录。为利用夜间时间进一步验证 EmoVoice 的七类情感控制，已启动 42 条诊断集：七类情感 × Conflict/Consistent × simple/strong/intense 三档提示。每组三档共享文本和参考说话人，以隔离提示强度因素；每个情感的一致/冲突样本则用于观察文本字面情感是否会压制目标语音情感。该诊断集不作为正式数据，只有经人工试听确认的配置才可进入正式生成。
13. 用户试听 Anger 三档提示后反馈：三条几乎没有可听差异，且均未体现愤怒。该现象被记录为“EmoVoice 文本提示对 Anger 的控制失效（当前文本/参考说话人条件下）”；它不是官方标签错误，也不构成对数据集情感标签的修改。后续先结合七类诊断集的人工试听，判断问题是否局限于 Anger 或普遍存在，再决定更换模型、引入参考情感语音或修改控制策略。
14. 七类诊断集已结束：计划 42 条，成功生成 41 条并下载到本机试听目录。基础质检按当前严格峰值阈值仅通过 16 条；其中一部分只因转码后峰值略高于 1 而被标记，文件仍可播放。另有三条明显异常超长（74.40、78.38、165.26 秒），已在本机 README 中单独标识，正式生成前必须加入峰值限制和最大时长过滤。缺失的第 42 条及其错误原因待后续定位，不影响当前主观试听。

## 非致命警告

CosyVoice 的 ONNX 前端寻找 CUDA 11 的 `libcublasLt.so.11` 未成功，因此该前端回退到 CPU；主模型已能进入 0 号 GPU。当前先以正确性为目标，不在冒烟阶段重装整套 CUDA/ONNX 环境。
