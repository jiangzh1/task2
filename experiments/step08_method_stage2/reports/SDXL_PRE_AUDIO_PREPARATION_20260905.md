# SDXL 与阶段二：完整语音到齐前的准备记录（2026-09-05）

## 已完成

1. SDXL Base 1.0 单文件 checkpoint 与本地 `sdxl-vae-fp16-fix` 的离线加载器已实现。
2. 官方 Latent-CLIP `epoch_34.pt` 已在 CPU 验证：直接输入 `[B,4,64,64]` SDXL latent，输出 640 维嵌入；输出和输入梯度均有限；编码器已冻结；没有调用 VAE decoder。
3. 版本 B 图片清单完成：12,930 样本、3,554 条图片路径；无缺失、无损坏、无跨 split 字节相同图片。
4. SDXL latent 缓存脚本已支持独立本地 VAE、断点续跑、确定性 mode latent 与 VAE scaling factor 记录。
5. 阶段一 SDXL 正式训练入口已实现：读取真实特征和训练索引、冻结 SDXL Base、保存/恢复仅论文新增模块的 checkpoint，避免复制基础模型权重。
6. 阶段二已修复正式训练维度接口：256 维阶段一条件与 640 维 Latent-CLIP 嵌入分别使用两层 GELU 双塔投影头，再进行三维批内偏好评分；CPU 冒烟通过。

## 尚未执行，原因

- 3,554 张 SDXL VAE latent 的实际编码需要 GPU；当前两张 GPU 均按用户要求持续进行 TTS，因此未抢占 GPU。
- 完整 SDXL Base 的实际 GPU 装载、14 条真实特征训练/最终图生成，均保留为所有准备完成后的最后验收，不作为本阶段的替代。
- 全量真实音频特征、正式训练和实验必须等待完整音频，不提前运行。

## 已知环境边界

CPU 离线尝试装载完整 SDXL Base 单文件时被服务器资源管理终止，未生成预检报告；这不构成模型或数据错误。后续借用一张 GPU 做最终验收时，先执行 SDXL GPU 资产预检。
