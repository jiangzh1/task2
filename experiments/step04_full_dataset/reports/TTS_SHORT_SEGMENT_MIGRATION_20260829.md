# 全量语音短分段迁移报告（2026-08-29）

## 目的

修复原始 55 词分段对 EmoVoice-PP 仍过长、经常被跳过的问题，同时保留全部已经成功的生成结果。

## 迁移策略

- 新建独立的 `full_tts_pp_hashsafe_v2` 工件和音频目录；旧目录保持原样，可随时审计和回退。
- 已成功的 4,219 个 16 kHz 分段通过硬链接复用，不复制、不删除、不重新生成。
- 已拼接完成的 2,137 条完整音频同样通过硬链接复用。
- 仅将旧队列中 20,562 个未成功父分段重新拆分；每个新待生成分段最多 20 个英文词。
- v2 每批只处理 8 个分段，缩短单批等待和异常影响范围；每个分段最多可重试 4 次。

## 迁移结果

- 旧分段总数：24,781。
- v2 分段总数：59,659。
- 复用成功分段：4,219。
- 重新切分的未成功父分段：20,562。
- 复用完整样本：2,137 / 12,930。
- v2 首批 8 个待生成分段长度：15、17、16、20、18、13、18、13 词，均不超过 20 词。

## 当前运行状态

v2 监督任务已经启动，并在 GPU 0 执行第一批短分段。每一批结束后会自动转为 16 kHz、更新 SQLite 状态并尝试拼接完整样本。若任务再次异常退出，v2 可从状态库继续，已成功音频不会被覆盖。

## 说明

由于旧成功分段可能仍含 21–55 词，迁移后整个目录中存在少量超过 20 词的已成功旧分段；它们不再进入待生成队列。20 词是本次针对未成功项的安全阈值，而非删除历史成果的规则。
